Proposed Enhancements to Stock Audit Software
1. Group-wise / Subgroup-wise Stock Take Provision
Objective
To streamline the stock audit process by enabling department-wise inventory segmentation into Groups and Subgroups for better control, monitoring, and reporting.
Current Process
• Stock audits are conducted at the department level.
• Users can select one or more departments for stock audit.
Proposed Workflow
Step 1: Audit Initialization User should be able to select:
• Store Name
• Audit Date
• Department
• Group
• Subgroup

Step 2: Data Pull
• System should pull only the selected Group/Subgroup inventory from ERP into the Audit System.

Step 3: Scanning Process
Users scan only the selected category items. System should track:
• Zone-wise coverage
• User-wise scanning activity
• Real-time scanned quantity

Step 4: Reporting System should generate:
• Group-wise discrepancy report
• Subgroup-wise discrepancy report
• Zero-scan report
• Final audit summary report

2. Decimal Quantity Input via Scanner
Objective
To eliminate manual entries for weighted items (UOM: KG) such as Fruits & Vegetables, Souk items, and similar categories.
Current Process
• Auditor weighs the item.
• Prepares a manual sheet containing Item Number, Item Description, and Quantity.
• Quantity is manually entered into the Audit System.
Proposed Workflow
Scanner should allow quantity entry with decimal values such as 1.25, 2.50, and 0.75.

System should:
• Accept decimal quantities based on Item UOM.
• Restrict invalid quantity formats.
• Auto-round quantities based on predefined business rules if required.

Expected Benefits:
• Reduction in manual data entry
• Reduced correction efforts
• Improved inventory accuracy
• Faster audit completion
3. Group-wise and Subgroup-wise Reporting Requirement
Current Process
• Download All Pending Items Report contains only zero-scan items.
• Download Consolidated Discrepancy Report excludes zero-count items.
Proposed Requirement
Reports should include complete discrepancies including zero-count items.

Required Report Fields:
• Sr. No
• Shop Code
• Item Code
• Item Description
• Department Name
• Group Name
• Subgroup Name
• System Quantity

• Physical Quantity
• Book Quantity
• Variance Quantity
• Variance Value
4. Excel Upload Tool for Recounted Items
Objective
To simplify the recount adjustment process and eliminate manual scanner entries for revised quantities.
Current Process
• Audit team updates recount quantities manually in Excel.
• Differential quantities are punched manually into scanners.
• TB upload is completed in ERP after recounting.
• Adjustment report is downloaded for sign-off.
Proposed Workflow
Step 1: Download Recount Sheet
System should generate an Excel template containing:
• Item Code
• Item Description
• Item Value
• System Quantity
• Physical Quantity
• Variance Quantity
• Variance Value

Step 2: Quantity Update
• Audit team updates only revised quantities in the Excel sheet.

Step 3: Excel Upload
• User uploads the updated Excel file into the Audit System.

Step 4: System Update
• Automatically update recounted quantities.
• Overwrite previous count quantities with the latest recount quantity.

Step 5: Audit Log System should maintain:
• Upload date & time
• User details
• Before vs. after quantity history

Step 6: TB Upload into ERP
Expected Overall Benefits
* Simplified audit execution
* Reduced manual intervention
* Improved stock accuracy
* Faster reconciliation process
* Better audit traceability
* Enhanced reporting and analysis
* Reduced operational errors
* Improved accountability through audit logs
